# 项目化会话与 Harvis 路由规格

## 目标

1. 用户提出图片、海报、音乐或 BGM 创作请求时，主会话可以直接获得并调用 `harvis_creative`。
2. 左侧栏保持单一信息层级：顶部是功能入口，随后是“项目”及项目内会话，不再分成会话筛选区和会话列表区。
3. 点击“新对话”先进入无持久化的草稿页；发送第一条消息时才创建会话，并绑定当前选择的项目工作目录。
4. 项目使用真实工作目录作为稳定标识，不新增会话数据库迁移。

## 信息架构

- 顶部功能入口中的“会话”改为“新对话”。
- “项目”区域按文件夹展示普通会话；文件夹子项为会话。
- `IM 会话` 与 `CLI 会话` 是固定系统项目。
- 普通会话的项目由 `session.workspace_root` 决定；未单独设置时继承全局工作区。
- 新建项目会在全局工作区下创建真实目录，随后可直接作为新会话工作区。

## 草稿会话

- 新对话页面不立刻写入数据库。
- 草稿输入区保留附件、模型、权限、人员、技能等现有能力。
- 第一条消息提交时依次执行：创建会话、写入项目工作区、切换到正式会话、发送消息。
- 发送失败时保留已创建会话和用户输入记录，便于重试与诊断。

## Harvis 路由

- `media` 工具组必须包含 `harvis_creative`。
- 轻量路由提示明确把图片、海报、音乐、BGM 和 Harvis 创作请求路由到 `workflow`。
- 工具仍由现有设置中的 Harvis 开关控制；关闭时不绕过权限或配置。

## 兼容性

- 不修改现有会话表结构。
- 不改变 IM、CLI、模型选择、附件、权限、技能和人员调度的底层接口。
- 旧会话自动按已有工作目录归组；没有工作目录的会话归入默认工作区项目。
- 收起侧栏时仅显示功能图标，不渲染不可读的项目树。

## 验收

- 路由单元测试验证 `media` 包含 `harvis_creative`。
- 项目归组单元测试覆盖默认工作区、多个工作区、空项目、IM、CLI 和 Windows 路径大小写去重。
- 组件测试覆盖项目展开、会话选择、新建项目和收起态。
- 前端测试、Web 构建、Rust 测试和 Tauri NSIS 打包全部通过。
