# 小亨 WorkBuddy 统一工作台 UI 规格

## 目标

把当前“应用功能侧栏 + 会话二级侧栏”的双层结构重构为单一全局侧栏。侧栏上方承载模块入口，下方持续显示全部会话；所有业务页复用统一工作台框架，会话页采用内容优先的消息流和悬浮输入区。

## 信息架构

1. 全局侧栏顶部依次提供新对话、对话、线上营销工作台、AI 创作、市场、工具、定时任务、长期记忆和审计入口。
2. 线上营销工作台保留素材库、数据看板、商摄快剪三级入口；AI 创作保留音乐和图片入口。
3. 功能区下方是独立可滚动的会话区，保留对话、IM、CLI 三类筛选、检索、历史分组、删除和新建能力。
4. 用户账号、最小模式、主题与设置继续位于侧栏底部。
5. 侧栏收起后只显示矢量图标和会话分类按钮，不渲染会话标题，避免狭窄区域溢出。

## 会话页面

1. 移除 Chat 内部会话侧栏，主区直接占满应用工作区。
2. 顶栏只保留当前会话标题、会话来源和 Todo/Tools/Artifacts 过程入口。
3. 消息流最大宽度 920px 居中；用户消息使用右侧弱色气泡，AI 回复使用无重边框的内容块。
4. 输入区固定在底部中央，附件位于输入框上方，模型、权限、技能等选择器在同一操作层。
5. 工具调用、计划和产物继续显示，但视觉层级低于消息正文，且可展开收起。

## 其他页面

所有页面使用统一的页头、工具栏、内容边距、卡片、表单、空状态、锁定状态和弹窗规则。数据密集页面允许全宽，普通设置和表单使用受控内容宽度。不得使用 Emoji 作为结构图标。

## 架构决策

会话数据与动作仍由 Chat 组件持有。新增全局会话导航组件，通过 React Portal 渲染到 App 侧栏提供的宿主节点。这个方案不搬迁会话 API 和 Redux 状态，可最大限度降低现有发送、IM、CLI、附件、任务面板和会话恢复功能的回归风险。

## 验收

- 应用任意页面都只显示一个左侧栏。
- 会话列表位于全局侧栏下半区，点击会话自动进入对话页面。
- 切换模块不会清空会话、输入草稿或附件。
- 浅色、深色、展开、收起状态均无文字重叠。
- 支持 `prefers-reduced-motion`。
- 单元测试、TypeScript、Vite 和 Windows NSIS 构建全部通过。
