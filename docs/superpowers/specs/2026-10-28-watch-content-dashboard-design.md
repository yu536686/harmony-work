# 腕表如诗内容看板与媒体能力设计草案

状态：用户已确认并执行。本文保留目标设计；实际实现、部署与验证边界以实施台账及 `docs/releases/windows-1.1.4-rc1.md` 为准，不能将设计中的验收条款直接视为全部实测通过。

## 1. 目标与范围

- 保留线上营销工作台现有素材库，在其导航中新增「腕表如诗内容看板」。
- 用 Harmony Work 客户端界面覆盖现有腕表资料库网页的全部用户功能；继续复用 231 上的业务服务及数据，不复制 NAS 素材或重建业务数据库。
- 为新看板及现有素材库提供可流式播放的视频预览、按需加载的图片预览、统一上传任务窗口，并衔接客户端登录状态。
- 同时支持 Windows 和 macOS。共享业务规则，界面遵循两端现有设计，macOS 使用项目已有原生窗口和控件能力；不承诺所有内容页面均为原生 SwiftUI。
- 原资料库网页保留为备用入口；现有素材库、目录、数据看板和用户数据保持不变。

## 2. 导航与信息架构

「线上营销工作台」下保留现有入口，增加「腕表如诗内容看板」。仅营销用户及已获授权的管理员可进入；服务端逐请求校验，不能仅依赖客户端隐藏入口。

看板由四个一级视图组成：

1. 已拍摄内容：按品牌、系列、关键词筛选素材，查看素材及研究详情。
2. 型号检索：文字或图片查询、查看研究过程、研究结果及其来源。
3. 共享档案：搜索和查看共享腕表档案与证据。
4. 上传素材：选择品牌、查看个人上传和手动触发分析。

全局的「上传任务」入口在素材库和看板均可访问；任务在两处共享，但必须显示各任务的所属来源和目标。

## 3. 界面设计

### 3.1 已拍摄内容

```text
线上营销工作台 / 腕表如诗内容看板                      上传任务  打开网页
已拍摄内容 | 型号检索 | 共享档案 | 上传素材
品牌 [全部品牌 v]  系列 [全部系列 v]  搜索 [型号、系列或文件名     ] [搜索]
拍摄素材 81    已分析  …    已建索引  …                     [刷新]
┌───────────────────────────┬──────────────────────────────────┐
│ 素材列表                  │ 已选择素材                       │
│ [封面] 品牌 / 系列        │ [视频或图片预览                 ] │
│        型号 / 文件名      │ 品牌 / 系列 / 型号 / 来源        │
│ [封面] 品牌 / 系列        │ [放入会话] [保存] [打开详情]     │
│ 更多结果 / 翻页           │ 研究档案与来源                   │
└───────────────────────────┴──────────────────────────────────┘
```

- 此图为布局示意，统计数字取自接口，不使用固定示例值。列表优先显示封面、品牌、系列和文件名；未选择时显示空状态。
- 点击素材在详情区域预览；窄窗口时详情进入独立子页或弹层，不能遮挡列表操作。
- 「放入会话」需用户主动确认，将授权获取的原文件准备为会话附件；预览不触发完整文件下载。
- 所有网页现有的管理员编辑、资料信息、来源展示和外部播放入口需保留；普通用户看不到无权限操作，服务端仍须校验。
- 原网页仅作补充入口，不能作为缺失功能的唯一实现。

### 3.2 型号检索

```text
型号检索
[文字检索] [图片检索]
型号或描述 [                                      ]  [开始检索]
研究状态   正在核对型号 → 查询来源 → 分析 → 匹配拍摄内容
结果       型号 / 品牌 / 关键特征 / 匹配素材
依据       来源链接、图片和证据 / 需人工核对的提示
```

- 图片检索提供选择文件、更换、移除、格式和大小提示；以服务端实际限制为准，当前网页图片检索限制 8 MB。
- 任务由服务端执行并查询状态；显示等待、处理中、完成、部分结果和失败原因，不伪造百分比。离开页面后返回仍可查看当前用户有权限查看的任务。
- 检索结果应与网页一致，保留参考图片、来源、匹配素材和不确定性提示；不把 AI 结果呈现为已核实事实。

### 3.3 共享档案

搜索框和档案列表展示品牌、完整型号、主要特征和更新时间；进入详情后展示已保存字段、图片、来源和对应素材。保留网页现有编辑权限规则和审核信息；无结果、来源失效和请求失败均有明确状态。

### 3.4 上传素材与统一上传任务

```text
上传素材                              [上传任务  2]
保存品牌 [请选择 v]   [选择文件] [开始上传]
我的上传：文件名 | 保存状态 | 分析状态 | 操作

上传任务
文件 A   ███████░░░  72%   速度 / 剩余时间       [暂停] [取消]
文件 B   已传输，等待 NAS 保存                    [详情]
文件 C   失败：网络中断                           [重试]
```

- 统一窗口提供队列、目标、每文件进度、速度、暂停、继续、重试、取消及错误原因；不阻塞切换页面。
- 分别显示等待、核验、上传、服务端校验、保存 NAS、完成和失败，只有服务端确认保存后才标记完成。
- 使用服务端确认偏移量、分片校验和现有续传接口；断线恢复与重新启动后续传需检查文件身份、账号、上传目标和服务端任务仍有效。文件被修改、移动或任务过期时说明原因并允许重新选择，不自动覆盖原文件。
- 文件来源、支持格式和大小上限由服务端返回；231 网页当前说明单文件最多 20 GB、并行两个文件，最终以上线配置和验证为准。现有素材库上传的目标与格式规则不因新增看板改变。
- 上传成功与 AI 分析分开：默认不自动分析，用户可在「我的上传」选择已入库素材后手动发起，显示任务状态和结果。
- 应用关闭后任务记录可恢复；进程退出时不承诺后台继续传输。删除任务记录不等于删除已保存的素材；取消操作明确说明影响。

## 4. 媒体预览与公网链路

- 客户端按资源能力优先使用缩略图和流式视频；Jellyfin 可用且条目映射可信时，经受控媒体服务请求播放信息，支持直接播放及必要时转码。兼容性不足时给出可操作的降级方式，不静默下载超大原文件。
- 未关联 Jellyfin 的图片或视频继续走现有素材服务的受控预览，不能为了统一预览而漏掉现有素材。独立验证 Windows WebView2 与 macOS WebKit 的格式、Range、播放列表和分片兼容性。
- 播放按需缓冲而非下载完整文件；只有保存、系统打开或附加到会话等用户操作需要原文件时才获取本地文件，并遵守工作区权限与清理策略。
- 公司公网域名和非标准 HTTPS 端口指向公司网络，服务及媒体流量不经腾讯云服务器中转。可评估复用现有 8443 及公司内网代理；证书、域名、NAT、端口占用和从外网可达性均需现场核实后决定，本文不指定新增映射。
- 服务端验证登录、营销角色和具体资源权限，播放票据短期有效且限制资源与用途；播放清单、分片、Range、封面、原文件及续传接口均应受保护。Jellyfin 管理密钥不进入客户端、网页、播放 URL 或日志。
- 在不中断播放前提下设计票据续期、客户端断开后的会话失效与权限撤销；不把未经验证的权限映射视为已满足。

## 5. 登录与权限

- 已登录且具有营销权限的用户直接进入看板；未登录用户显示登录入口，非营销用户显示无权限提示。客户端与资料库通过服务端验证的短期、一次性授权交换建立用户级会话，不传递用户密码或共享管理员会话。
- 保留 231 的本地账号网页登录作为原系统能力；客户端接入使用 Harmony Work 用户身份，不改变原有账号数据。管理员编辑、分析和查看任务的权限需以现有服务规则为基准逐项核对。
- 退出登录、权限变化、授权过期、资料库或官网不可达均给出可理解的提示；按服务端策略撤销或拒绝后续请求，不通过隐藏菜单替代鉴权。

## 6. 关键异常与安全

- NAS 不可达时显示服务不可用，禁止因扫描失败或空目录而删除、覆盖已有索引；保留此前记录。
- 区分网络中断、无权限、服务不可用、文件缺失、编码不兼容及转码繁忙；提供重试或系统打开等适当选项。
- 图片、视频和文件上传应限制类型、大小和路径，避免路径穿越；不得在前端泄露 NAS 路径、上游密钥或其他用户文件信息。上传到既定 NAS 位置时保留原服务的同名不覆盖策略。
- 媒体直连和登录涉及生产安全，发布前需评审令牌生命周期、访问日志脱敏、限流、审计和回退。实际下载原文件的权限与预览权限需单独校验。

## 7. 验收标准

1. 营销用户在两端看到新入口；标准用户不能通过界面或直接请求获取未授权资料。现有素材库和营销功能不退化。
2. 四个视图逐项对照线上网页：筛选、详情、型号文本/图片研究、任务进度与来源、共享档案、上传历史、手动分析、管理员操作和错误状态均可用。
3. 大视频开始播放不先下载完整文件；直接播放和转码分别测试，拖动进度与网络中断可恢复；无 Jellyfin 关联的素材有可用的受控回退。缩略图与原图按需加载。
4. 上传在断网、暂停、应用重启、文件修改、失权和 NAS 故障场景下状态准确；成功以服务端确认保存为准，不覆盖已有文件。
5. 客户端已有登录状态可安全进入；退出、撤权及过期后无权继续请求。播放列表、分片、缩略图与原文件均不能越权访问。
6. 公司内网与真实外网分别测试，确认媒体和上传流量不经腾讯云服务器；检测 HTTPS 证书、带端口地址、Range、速度及并发负载。
7. 兼容 Windows、macOS 的文件选择、播放器及窄窗口布局；macOS 原生能力与 WebView 边界以实际实现验收，不作超出实现的宣传。
8. 上线前保留原网页和原素材库回退；记录配置、权限变更、部署版本及测试结果。

## 8. 待用户确认

- 「腕表如诗内容看板」四个视图及布局是否符合使用习惯。
- 统一上传任务窗口是否应显示所有来源的任务，还是仅显示当前模块任务。本文默认统一显示并标注来源。
- 默认保留原网页入口，并将「发送给小亨」作为需要下载原文件的主动操作；是否符合预期。
- 本文描述的是目标设计。现有服务接口覆盖、统一登录方案及媒体权限方案仍需技术验证后形成实施计划。
