# Harmony Work 品牌与对话执行体验设计规格

> 状态：已确认，可进入实现计划阶段
> 目标版本：`1.3.0-alpha.x`
> 基线提交：`16bfe7b`
> 开发分支：`feat/harmony-work-conversation-experience`
> 最后更新：2026-09-15

## 1. 目标

本次迭代同时完成两项产品级升级：

1. 将桌面产品的用户可见品牌从“小亨 WorkBuddy”全面更新为 **Harmony Work**。
2. 将对话中的 Agent 执行过程重构为可理解、可折叠、可追踪、可继续反馈的工作流体验。

完成后，用户应能在一个对话页面中清楚看到：小亨正在做什么、已经完成什么、调用了哪些工具、生成了哪些成果，以及如何针对成果继续提出修改意见。

## 2. 不可变产品边界

以下约束优先级最高，后续实现不得自行改写：

### 2.1 产品与 Agent 分离

- 产品名称：**Harmony Work**。
- Agent 中文人格名称：**小亨**。
- 英文界面中的 Agent 名称：**Xiaoheng**。
- 对话输入框中文占位文案：**给小亨发送消息**。
- “你是谁”等身份问题必须回答“小亨，是 Harmony Work 中的 AI 工作伙伴”，不得回答 Harmony Work、WorkBuddy、小珩、小衡、小行或 Piscis。
- Harmony Work 是承载对话、项目、工具、创作、团队与成果的产品；小亨是产品中的默认自主 Agent。

### 2.2 兼容性边界

- 保留 Tauri `identifier`、用户数据库路径、配置路径和历史会话标识，避免升级后丢失用户数据。
- 内部二进制名、数据库字段名和兼容层标识可以暂时保留旧名称，只要不出现在用户界面、安装流程、日志导出说明或公开文档中。
- 不借品牌迭代重写 Codex app-server、MCP Host、Harvis、IM、StaffDeck、账号同步或现有业务模块。
- 不强制简单任务创建 Todo 或计划；执行时间线必须能直接呈现没有计划工具的任务。

### 2.3 思考信息边界

- 展示模型主动输出的公开说明、运行阶段、计划摘要和工具轨迹。
- 不启用、不展示、不持久化原始隐藏推理或完整 chain-of-thought。
- 展开“思考”时显示的是面向用户的简洁推理摘要，例如“正在比较三份 CSV 的字段差异”，不是模型内部 token 流。
- 工具参数和结果必须经过脱敏、截断和结构化摘要；API Key、Token、Cookie、密码和 Authorization Header 永不显示。

## 3. 视觉与品牌规范

### 3.1 品牌资产

- 使用用户提供的 Harmony Work 文字形象作为主标识来源。
- 输出适配浅色背景的透明文字标识：`Harmony` 使用深色，`Work` 使用品牌紫色。
- 输出适配深色背景的反白文字标识：`Harmony` 使用白色，`Work` 使用浅紫色。
- 使用用户提供的紫色 `H + 机器人` 图形作为应用图标来源。
- 从同一源图生成 Windows 安装器、应用程序、桌面快捷方式、开始菜单、任务栏、托盘和系统尺寸图标，禁止各处继续混用旧图标。
- 图标缩放需保留安全边距，避免 Windows 小尺寸图标裁切主体。

### 3.2 产品用色

- 品牌主色：`#7653E8`。
- 品牌浅色背景：`#F1EDFF`。
- 主文字：`#1F2024`。
- 次级文字：`#70737B`。
- 页面背景：`#F7F7F8`。
- 内容表面：`#FFFFFF`。
- 默认边框：`#E7E7E9`。
- 成功状态：`#2C9B62`。
- 警告状态：`#C98724`。
- 错误状态：`#D84D4D`。
- 品牌紫色只用于品牌、选中状态和主要操作，不把整个界面做成单色紫色主题。

### 3.3 组件节奏

- 使用现有 `design.md` / Theme Token 体系；若仓库不存在独立 `design.md`，则把本节 Token 合并到现有主题文件，不新建互相冲突的第二套设计系统。
- 卡片圆角默认 8px；输入框与对话编辑器可使用 10-12px。
- 微交互 150-240ms，使用 `opacity` 与 `transform`，不得通过动画宽高造成布局跳动。
- 所有动画遵循 `prefers-reduced-motion`。
- 图标统一使用 Lucide，用户提供的品牌图标除外；不使用 Emoji 作为功能图标。

## 4. 页面信息架构

### 4.1 左侧栏

- 左侧栏继续承载一级功能入口和项目会话列表，不恢复双侧栏结构。
- 顶部显示 Harmony Work 图标和文字标识。
- 所有项目、IM、Harvis、团队、市场等现有入口保持路由和权限逻辑不变。
- 用户账户入口继续位于左下角。

### 4.2 对话主区

- 顶部只保留会话标题、必要的会话操作和右侧工具面板开关。
- 现有“活动 / 待办 / 工具 / 成果”顶部四按钮不再作为主要入口。
- 活动、计划和工具执行改为插入当前对话轮次的结构化执行时间线。
- 成果、任务摘要、浏览器和终端统一进入右侧工具面板。

### 4.3 右侧工具面板

- 桌面宽屏：固定在对话右侧，默认宽度 420px，允许在合理范围内调整。
- 中等窗口：压缩到 340px，并保持对话区最小可读宽度。
- 小窗口：以覆盖式抽屉打开，不把输入框或审批弹窗挤出可视区域。
- 关闭面板后，对话区恢复完整宽度，当前标签和预览状态保留。

## 5. 对话执行时间线

### 5.1 每轮结构

每个用户消息对应一个执行轮次，顺序为：

1. 用户消息。
2. 小亨标识。
3. 当前公开思考摘要或阶段说明。
4. 结构化执行步骤。
5. 最终回复。
6. 可选成果卡片。

历史消息不得把不同轮次的工具调用混在同一时间线中。

### 5.2 步骤状态

| 状态 | 图标 | 默认展开 | 行为 |
| --- | --- | --- | --- |
| 待处理 | 空心圆 | 否 | 灰色弱化 |
| 执行中 | 品牌色旋转指示器 | 是 | 动态更新摘要 |
| 等待批准 | 盾牌或锁 | 是 | 展示批准说明和操作 |
| 已完成 | 绿色勾选 | 否 | 显示一行完成摘要 |
| 失败 | 红色警告 | 是 | 显示原因与恢复操作 |
| 已取消 | 灰色停止 | 否 | 保留取消时间与原因 |

完成一个步骤时：

- 停止运行动画。
- 将状态替换为完成图标。
- 生成一行可扫描的结果摘要。
- 自动折叠详细过程，但保留用户手动展开能力。
- 下一步骤开始时自动滚动到可视区域，不能强制抢走用户主动滚动位置。

### 5.3 展开内容

步骤展开后可以包含：

- 公开思考摘要。
- 已读取文件及数量。
- 调用的技能或工具名称。
- 命令、网页、文件变更等经过清理的摘要。
- 生成的中间成果。
- 错误与重试记录。

默认隐藏完整工具输入和大段输出。高级详情需要二次展开，并限制最大高度、支持复制、对敏感字段脱敏。

### 5.4 简单任务

- 没有 Todo 的简单问答只显示流式回复，不创建空时间线。
- 只有一个工具调用时显示一个紧凑步骤。
- 多工具或有计划的任务按计划项聚合；无法可靠归属的工具调用放入“其他执行”步骤。
- UI 不得诱导 Agent 为了显示效果反复调用 `plan_todo`。

### 5.5 流式与完成状态

- 首个公开文本到达前显示轻量运行指示，不使用长期占位气泡。
- 公开思考摘要与最终回答分开，不能把思考文本写进最终答案。
- 最终回答继续逐字流式呈现。
- `done`、`cancelled`、`error` 必须结束所有运行动画。
- 重新打开历史会话时，从持久化消息、计划、工具调用与成果中重建静态时间线，不伪造实时状态。

## 6. 右侧工具面板

### 6.1 成果

- 列出当前会话生成的文件和链接，按最近更新排序。
- 根据类型提供图片、文本、代码、网页和可支持文档的内嵌预览。
- 不支持内嵌的 Office 文件显示文件摘要、大小、路径，以及“打开”“另存为”“在文件夹中显示”。
- 预览加载失败时提供明确错误与外部打开操作，不能显示空白区域。
- 预览工具栏提供“注释”模式；不在预览下方保留常驻评论输入框。
- 进入注释模式后，用户直接在文本、代码、图片、PPT 页面或视频画面上选择目标，并在选区附近填写修改要求。

### 6.2 任务摘要

- 显示本轮目标、已完成步骤、关键决策、失败/重试和成果列表。
- 摘要从结构化事件生成，不额外触发模型调用。
- 可复制为 Markdown，但不默认写入对话。

### 6.3 浏览器

- 展示 Agent 当前或最近使用的浏览器目标、URL 和状态。
- 支持应用现有浏览器能力时嵌入预览；无法嵌入时显示 URL、截图或打开入口。
- 页面注释至少携带当前 URL、页面标题、用户评论和可用的目标描述。
- 同源或可控页面优先记录 DOM 元素/文本选区；跨域页面和不可控 WebView 使用当前截图的归一化矩形区域，不以跨域注入为实现前提。

### 6.4 终端

- 展示本轮命令执行摘要及最近输出。
- 只读预览为默认状态，不自动创建新的 Shell 会话。
- 保持现有审批机制；查看终端不能绕过命令批准。
- 输出中的密钥、认证 Header 和敏感环境变量必须脱敏。

## 7. 注释与下一轮修改

### 7.1 支持对象

- 整个成果文件。
- 文本选区或代码行区间。
- 图片、PPT 页面或视频帧中的点位/矩形区域，坐标以 0-1 归一化保存。
- 浏览器页面、DOM 元素、文本选区或截图区域。
- 终端中的命令或输出区段。

### 7.2 交互规则

- 用户从预览工具栏进入“注释”模式，按钮明确显示“正在注释”。
- 文本和代码通过选择文字或行号建立锚点；图片、幻灯片和视频帧通过点击或拖动框选建立锚点。
- 选区建立后，在目标附近显示轻量浮层，填写修改要求并点击“添加到对话”。
- 已确认的选区保留编号标记，同时在主会话输入框上方生成结构化批注标签。
- 用户可以连续添加多个批注，最后在主输入框补充整体要求，统一发送给小亨。
- `Esc` 取消当前未确认选区并退出注释模式，不删除已经暂存的其他批注。
- 发送失败时保留输入内容、批注标签和原始选区；恢复后可以直接重试。
- 右侧面板关闭或切换标签时，未发送批注进入会话级本地草稿；除非用户主动删除，否则不得静默丢失。

### 7.3 数据模型

```ts
interface WorkbenchCommentContext {
  targetType: "artifact" | "browser" | "terminal";
  targetId?: string;
  uri?: string;
  title: string;
  selection?:
    | { type: "text_range"; start: number; end: number; excerpt: string }
    | { type: "line_range"; start: number; end: number; excerpt: string }
    | { type: "image_region"; x: number; y: number; width: number; height: number }
    | { type: "dom_element"; selector?: string; role?: string; label?: string; excerpt?: string }
    | { type: "page"; url: string };
  comment: string;
}
```

### 7.4 发送行为

- “添加到对话”只暂存批注，不立刻启动 Agent；点击主输入框的发送按钮后，才创建新的用户消息并启动下一轮执行。
- 消息正文显示用户整体要求；一个或多个目标上下文以结构化附件传给运行时。
- 文件目标必须沿用当前工作区访问和外部文件授权规则。
- 发送前允许用户编辑、移除或重新定位单个批注。
- 发送失败时保留草稿和选区，不清空输入。

## 8. 事件与状态架构

### 8.1 现有事件复用

继续复用当前 Codex app-server 适配层：

- `RunStatus`
- `TextSegmentStart`
- `TextDelta`
- `ToolStart`
- `ToolEnd`
- `PlanUpdate`
- `PermissionRequest`
- `ContextUsage`
- `Done / Cancelled / Error`

### 8.2 新增前端聚合层

新增纯前端的 `TurnExecutionModel` 聚合器，将一个轮次的事件映射为：

```ts
interface TurnExecutionModel {
  turnId: string;
  sessionId: string;
  status: "running" | "waiting_approval" | "completed" | "failed" | "cancelled";
  publicSummary?: string;
  steps: ExecutionStep[];
  artifacts: SessionArtifact[];
  startedAt?: string;
  completedAt?: string;
}
```

- 聚合器必须是纯函数，并通过单元测试覆盖乱序事件、重复事件、重连和历史重建。
- 不为 UI 新建第二套 Agent Loop。
- 只有现有事件无法表达公开摘要时，才扩展 Rust `WorkBuddyEvent`；不得直接把 app-server 原始事件泄漏给组件。

### 8.3 持久化

- 首版继续以消息的 `turn_index`、`tool_calls_json`、`tool_results_json`、计划和成果表为事实来源。
- 用户手动展开状态、右侧面板标签和宽度保存在前端偏好中。
- 评论上下文随用户消息持久化，保证重启后仍能解释下一轮修改来源。

## 9. 代码边界

为避免继续扩大 `Chat/index.tsx`，实现时拆分为：

- `Chat/ExecutionTimeline.tsx`：轮次时间线。
- `Chat/ExecutionStepRow.tsx`：步骤状态和折叠详情。
- `Chat/turnExecutionModel.ts`：事件聚合与历史重建。
- `Chat/WorkbenchPanel.tsx`：右侧面板框架。
- `Chat/workbench/ArtifactsView.tsx`。
- `Chat/workbench/TaskSummaryView.tsx`。
- `Chat/workbench/BrowserView.tsx`。
- `Chat/workbench/TerminalView.tsx`。
- `Chat/workbench/CommentComposer.tsx`。
- `branding.ts`：用户可见产品名、Agent 名和兼容标识的统一常量。

组件通过明确 Props 接收状态，不直接读取数据库或拼装 app-server 原始事件。

## 10. 动效与可访问性

- 状态不能只依赖颜色，必须同时有图标和文字。
- 图标按钮提供中文/英文 `aria-label` 与 Tooltip。
- 时间线、折叠项、标签和锚点批注浮层支持键盘操作。
- 展开/收起使用 180-240ms 动效；完成态使用一次轻量过渡，不循环闪烁。
- 运行指示器只在真实运行时旋转。
- 输入框、审批弹窗和右侧面板不得互相遮挡。
- 1280x720 为最低完整功能视口，980x680 保持可操作，较窄窗口自动切换抽屉模式。

## 11. 测试与验收

### 11.1 品牌验收

- 全仓扫描用户可见“小亨 WorkBuddy / Xiaoheng WorkBuddy / Piscis”文案，只允许 Agent 人格、兼容代码或迁移测试中的“小亨 / Xiaoheng”。
- 窗口标题、托盘、安装器、快捷方式、关于页、欢迎页、登录页、设置页、README 和通知显示 Harmony Work。
- 安装后 Windows 桌面、开始菜单和任务栏使用新图标。
- 升级安装保留历史账号、会话、设置、技能和工作区配置。

### 11.2 对话验收

- 无工具问答不出现空时间线。
- 单工具、多工具、计划任务、等待审批、工具失败、取消和完成均有正确状态。
- 已完成步骤默认折叠，当前步骤默认展开。
- 重启并打开历史会话后，时间线内容稳定且没有“仍在执行”的假状态。
- 流式最终回复不重复、不丢字、不混入公开思考摘要。
- 工具详情不泄漏测试用密钥和认证信息。

### 11.3 面板验收

- 面板开关、标签切换、尺寸与状态恢复正常。
- 图片、文本/代码、网页链接、Office 文件均有可用预览或明确降级路径。
- 文件、文本行、图片区域和浏览器页面批注能组合为一条下一轮用户消息。
- 批注发送失败保留草稿、上下文标签和选区锚点。
- 面板在小屏幕不遮挡输入框、审批弹窗或保存对话框。

### 11.4 回归测试

- 前端单元测试与构建通过。
- Rust 主程序与 MCP Host 测试通过。
- 安装器离线运行时测试通过。
- Windows 远端完成 Debug 冒烟和 Release 安装包构建。
- 实测一轮无工具问答、一轮文件生成、一轮浏览器任务、一轮失败恢复。
- 安装包中无 Piscis 二进制或回退路径。

## 12. 非目标

- 不把右侧面板改造成完整 IDE。
- 不在本阶段实现多人实时协作评论。
- 不向服务器同步未发送的本地评论草稿。
- 不展示模型隐藏推理。
- 不替换 Codex app-server 或 WorkBuddy MCP Host。
- 不修改现有账号权限、API 计费、Harvis 业务模型和 IM 协议。

## 13. 已确认的视觉基线

已确认的原型采用以下组合：

- 单一左侧栏。
- 对话主区内嵌结构化执行时间线。
- 步骤级完成/运行/失败图标。
- 完成步骤自动折叠，当前步骤展开。
- 右侧工具面板承载成果、摘要、浏览器和终端。
- 成果与浏览器支持向小亨提交下一轮修改意见。
- 产品标识显示 Harmony Work，对话对象仍显示小亨。

该基线来自用户提供的产品视频、执行过程截图、右侧工具面板截图，以及 2026-09-15 确认的交互原型。
