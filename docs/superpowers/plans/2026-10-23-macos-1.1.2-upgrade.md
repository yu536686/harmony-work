## 2026-10-24 启动崩溃修复 R2

- 用户从 `/Applications/Harmony Work.app` 启动 1.1.2 时发生 SIGABRT。崩溃日志明确指向升级前备份校验：`unable to validate the inverted index for FTS5 table main.memories_fts: attempt to write a readonly database`。安装与构建的主程序 SHA-256 相同，不是下载或复制损坏。
- 根因：SQLite 的 FTS5 完整性检查内部执行 `INSERT ... VALUES('integrity-check')`；原校验用只读连接打开快照，导致包含全文索引的老数据库无法通过。之前仅用普通表模拟旧库，漏掉了该启动升级场景。
- 修复仅限 Mac 升级模块：原始数据库继续只读备份；私有快照用读写连接开启验证事务，检查后回滚，快照字节保持不变。未绕过完整性检查，未清空配置、会话或记忆。
- 回归先红后绿：新增外部内容 FTS5/WAL 数据库备份校验测试，并给原迁移夹具补齐真实全文索引。修复前 2 项报同样只读错误；修复后原生测试 306/306。前端 223/223、跨平台契约 36/36；完整 app/dmg release 构建通过。
- 真实旧库副本启动通过；随后保留旧应用为 `/Applications/.Harmony Work.before-fts-fix-20261024.app` 并替换本机正式安装位置，按正常 Mac 应用启动方式打开成功，历史会话已呈现。升级前备份保留 15 个会话、790 条消息、5 条记忆；既有数据库初始化会对重复消息去重，备份保留所有原始行。未修改该既有逻辑。
