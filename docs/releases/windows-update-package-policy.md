# Windows 全量与轻量更新发布规则

## 判定原则

当前轻量包是有兼容性门禁的应用文件覆盖包，不是全量安装器的压缩版，也不是任意版本间的二进制差分包。版本号大小不是选包标准；必须同时满足更新文件属于受管范围、外部依赖与兼容基线一致、已注册安装且运行环境健康、数据变更可恢复。

## 当前轻量包覆盖范围

- harmony-work.exe：内嵌前端页面、样式、图片、Rust 后端和客户端内更新逻辑。
- resources/workbuddy-mcp-host/**：自有 MCP host。
- resources/harmony-cut/**：自有 Harmony Cut 代码和资源；仅当现有 Python 包、FFmpeg 等依赖满足且无需改变时。
- licenses/** 和 resources/artifact-runtime/THIRD_PARTY_NOTICES.txt。
- 更新器自身的 WPF 进度窗口、校验与事务脚本由轻量 EXE 携带，在临时目录运行。

适合：界面与交互改进、会话/设置/业务逻辑修复、Rust 主程序修复、自有 MCP 工具或剪辑业务逻辑修复、与现有外部运行环境兼容的新增功能。前端 npm 或 Rust crate 变化若已编入主程序且无需新增外置资源，也可采用轻量包。

## 当前实现必须采用全量包的情形

- 首次安装、安装损坏修复、缺少运行环境或无法通过轻量兼容性校验。
- 新增或改变受管范围外的外置资源：Codex、Playwright MCP、FlaUI MCP 等，包括升级其文件或增加其依赖。
- Node、Python 及其第三方包/原生扩展、Git、WeCom CLI、FFmpeg 或 WebView2 等运行时需要新增、升级或改变布局。
- 安装目录规则、卸载工具、快捷方式、系统注册、服务、权限模型或体系结构发生变化。
- 修改轻量包所有权清单以外的文件；须先实现受管范围、兼容门禁与回滚机制，再考虑未来轻量支持。

全量安装器当前会复用已存在的部分运行时。因此“改用全量包”不等于已有依赖自动升级：变更运行时版本时，必须同步更新 runtime-lock、版本检测、安装/迁移逻辑及测试；当前仅判断存在的逻辑不足以保证依赖版本迁移。

## 发布前检查

1. 比较资源与运行环境的精确 SHA-256 清单；不同则拒绝构建当前轻量包。
2. 轻量包只覆盖拥有的文件，安装前检查签名、依赖、写权限、空间、WebView2、运行进程和文件锁。
3. 覆盖前备份并写事务日志；新进程必须报告正确版本和健康 token，稳定运行后才提交，否则回滚文件。1.1.3-rc1 更新器另用当前 Windows 用户的 DPAPI 加密配置快照，校验事务、路径和完整性后才允许恢复；恢复失败保留证据并阻止自动重启。
4. 分别验证标准与嵌入式 Python 兼容配置、前端真实加载、核心工具导入、会话/设置/工作区保留。
5. 安装包使用不可变 CDN 地址，签名完成后验证原包与篡改包，再验证 CDN 全量下载 SHA-256；最后切换官网和更新频道。

## 数据迁移限制

事务回滚保护应用文件；1.1.3-rc1 还保护原有配置文件，但不自动撤销数据库、会话或工作区中的不可逆迁移。本轮数据库变更为新增表，旧版仍可读取既有业务记录；秘密字段保持旧版可识别的密文编码，独立视觉 Key 的新加密由失败回滚时的原配置恢复兜底。发生不可逆迁移的更新，无论全量或轻量，都必须另行设计数据备份、版本迁移、失败恢复与回退兼容策略。
